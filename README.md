# ToDo лист API

Учебный API для просмотра задач и их классификации по матрице Эйзенхауэра:

- Q1: важные и срочные.
- Q2: важные и несрочные.
- Q3: неважные и срочные.
- Q4: неважные и несрочные.

При запуске временное хранилище содержит четыре задачи. Данные хранятся в памяти
приложения и возвращаются к исходному состоянию при перезапуске сервера.

## Технологии

Python 3.10+, FastAPI, Pydantic, Uvicorn.

## Запуск

В терминале из папки проекта создайте виртуальное окружение:

```bash
python -m venv venv
```

Активируйте его в Git Bash на Windows:

```bash
source venv/Scripts/activate
```

Либо в PowerShell:

```powershell
.\venv\Scripts\Activate.ps1
```

Установите зависимости и запустите приложение:

```bash
pip install -r requirements.txt
uvicorn main:app --reload
```

API: http://127.0.0.1:8000/. Интерактивная документация: http://127.0.0.1:8000/docs.
Остановка сервера: `Ctrl+C`.

## Эндпоинты

| Метод | URL | Назначение |
| --- | --- | --- |
| GET | `/` | Приветствие и информация об API |
| GET | `/api/v1/tasks` | Все задачи и их количество |
| GET | `/api/v1/tasks/quadrant/Q1` | Фильтрация по квадранту Q1, Q2, Q3 или Q4 |
| GET | `/api/v1/tasks/status/completed` | Выполненные задачи; `pending` возвращает невыполненные |
| GET | `/api/v1/tasks/search?q=проект` | Поиск в названии или описании, минимум два символа |
| GET | `/api/v1/tasks/1` | Полная информация о задаче с указанным ID |
| POST | `/api/v1/tasks/` | Создание задачи, ответ 201 Created |
| PUT | `/api/v1/tasks/1` | Обновление переданных полей задачи |
| PATCH | `/api/v1/tasks/1/complete` | Завершение задачи с сохранением `completed_at` |
| DELETE | `/api/v1/tasks/1` | Удаление задачи, ответ 204 без тела |
| GET | `/api/v1/stats/` | Общее количество задач, статистика по квадрантам и выполнению |

Неверный квадрант возвращает 400. Поисковый запрос короче двух символов возвращает 422.
Несуществующая задача, неизвестный статус и отсутствие результатов поиска возвращают 404.

Маршруты задач находятся в `routers/tasks.py`, статистика — в `routers/stats.py`.
Оба роутера подключены в `main.py` с префиксом `/api/v1` и используют единый
список `tasks_db` из `database.py`. Pydantic-схемы находятся в `schemas.py`.
В Swagger UI маршруты сгруппированы тегами `tasks` и `stats`.
Документация ReDoc доступна по адресу http://127.0.0.1:8000/redoc.

## Создание и обновление задач

Пример тела POST-запроса:

```json
{
  "title": "Сделать практическую 3",
  "description": "Реализовать CRUD",
  "is_important": true,
  "is_urgent": false
}
```

`title`, `is_important` и `is_urgent` обязательны при создании. Название должно
содержать от 3 до 100 символов, необязательное описание — не более 500.
Нарушения схемы возвращают 422. Pydantic преобразует поддерживаемые строки
`"True"` и `"False"` в логические значения. Неизвестные поля игнорируются.
Сервер назначает ID, дату создания и квадрант, исходя из важности и срочности.

PUT изменяет только переданные поля. При изменении важности или срочности квадрант
пересчитывается. `description: null` очищает описание; остальные поля обновления
можно пропустить, но нельзя задавать им `null`. При завершении задачи сохраняется
дата `completed_at`, при возврате в невыполненные она очищается.
